# Espresso Lab — Espresso Physics Simulator v4.3.0

🌐 **公開アプリ**: https://imim100913-cell.github.io/espresso-physics-simulator/

スマホで「レシピを選ぶ → 抽出を見守る → 一杯を振り返る」を体験する、エスプレッソの学習用シミュレーターです。

## 一杯をつくる流れ

1. **レシピを決める** — バランス・フルーティー・しっかりコクのプリセットから選びます。そのまま抽出でき、挽き目・粉量・目標量・湯温・圧力は日本語のヒントを読んで調整できます。詳細設定はスイッチから表示します。
2. **抽出を見守る** — 計量 → 粉砕 → WDT（粉をほぐす） → タンピング → セット → 抽出と、作業ごとに場面が切り替わります。準備は計15秒です。進行状況、抽出時間、圧力、流量、カップの量が連動します。一時停止と再開ができ、目標量に達したら自動で結果へ。簡易モードではアニメーションを省略できます。GPUモードでは、途中までの計算で終了して結果を確認できます。バックグラウンド移行時は自動で一時停止します。
3. **一杯を振り返る** — レシピバランスの参考点と内訳、味の予測、最終値、全設定のスナップショット、途中4時点の数値、グラフを確認できます。提案された1項目を変えて再抽出すると、直前の一杯の点数・時間との比較が表示されます。

期待度の5段階評価とマイレシピは、この端末・ブラウザのlocalStorageに保存します。期待度は最近20件、レシピは30件までです。共有URLにはレシピ設定だけを含み、個人の評価は含めません。共有URLの設定は読み込み時に型・範囲を検証します。

## 推定値と参考点について

スマホの自動設定は軽量モデルです。GPU物理を選ぶと、対応端末では粉体MLS-MPM／Drucker–Prager、多孔質流と溶出、XPBD自由液体を実際に計算します。非対応端末や手動選択では簡易モデルを使います。**物性値は実機で未校正で、味・点数は参考予測です**。豆の産地・水・器具・操作などにより実際の抽出や味は異なります。

以下は簡易モードの計算です。GPUモードでは回収した液体・溶質からTDSとEYを求めます（[実装と検証範囲](docs/architecture/gpu-solver.md)）。

- 相対抵抗モデルから流量を求め、0.1秒ごとに抽出量を積算します。圧力のかけ方は一定圧・蒸らし・低下圧・ブルーミング・ターボ・カスタムに対応。カスタムは指やキーボードで操作しやすい数値入力です。
- 目標量に届いた時点を補間して終了します。120秒で届かないときは、完了扱いにせず実際の推定抽出量を表示します。
- 収率は抽出時間・挽き目・湯温などの経験的な式で推定。極端に流れが遅いケースでは濃度が非現実的にならないよう最終TDSを25%以内に制限します。途中の濃度は初期ほど高い単純化した曲線で、各サンプルに `EY = TDS × 抽出量 / 粉量` が成り立ちます。
- 再生、途中経過の表、グラフ、最終レポートは**同じ1回分の計算結果**を使います。結果は実行時の設定を固定しており、次のレシピの編集で過去の値が書き換わることはありません。
- 参考点は「収率20%への近さ40点 + 推定甘味25点 + 抽出ムラの少なさ20点 + 濃度9%への近さ15点」。未達時は合計40点が上限です。高い点数が好みに合うことを保証するものではありません。
- 時間の表記は準備15秒と抽出時間を区別します。流量はモデル内で `g/s` として扱います。グラフと途中表のTDSは、その時点のカップ全体の濃度です。

## 開く・開発する

GitHub Pagesまたは静的HTTPサーバーでそのまま動作します。ビルドや実行時のnpm依存はありません。

```sh
npm ci
npm start
# http://localhost:4173
```

準備工程は全端末で軽量なSVGの場面を表示します。3Dを有効にした場合は抽出の場面で3Dへ移り、グラインダーやタンパーは表示しません。3D表示とGPU計算はローカル同梱のバンドルを遅延読み込みします。バンドルやWebGLが使えない場合も、軽量な表示で抽出・数値・結果を利用できます。`prefers-reduced-motion` が有効な環境は自動では3Dを表示せず、GPU計算を選んだ場合もSVGの工程表示と数値を更新します。

## 検証

```sh
npm test
npx playwright install chromium
npm run test:e2e
```

システムのChromiumを使う場合:

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:e2e
```

モデルテストは目標量での終了、溶解成分の整合、圧力プロファイルの影響、120秒の未達、入力検証、極端な設定を検証します。ブラウザテストは初回導線・一時停止と再開・自動終了・再抽出と比較・保存と再読込・共有URL・保存不可時の動作・320px/横向き/デスクトップのレイアウト・アクセシビリティを確認します。

## 構成

- `index.html` / `index.css` — モバイルを中心に設計した3ステップの画面
- `js/brew-model.js` — DOMや3D表示から独立した計算と入力検証
- `js/brew-workflow.js` — 計量から抽出までの共通タイムライン
- `js/brew-illustration.js` — 各作業で必要な道具だけを映すGPU不要のアニメーション
- `js/journey.js` — 画面遷移、再生、レポート、保存、共有
- `js/app.js` — 既存の3DシーンとCanvasチャートの表示用クラス
- `tests/` — 計算と一連のユーザー操作のテスト
- `js/main.js` / `js/ui/` — v3の分割実装。現在の画面からは読み込みません

## 3D描画の刷新（v4.1）

[グラフィックス・物理レンダリング設計書](docs/architecture/graphics-physics.md) に、全体パイプライン、断面／粉体／湿潤のGLSL、液流とSSFR、精密造形、WebGPU連成の導入設計をまとめています。今回動く実装と、実機校正・大規模ソルバーとして残る開発は設計書の表で区別しています。

- 3DはThree.js **0.186.1**をローカルに同梱。断面、パック／液流のカメラ、3段階の画質を選べます。
- 閉じたバスケット形状の切断面、実際に穴の開いた底面、連続ベッドと表面微粒子、圧密／湿潤のシェーダー、動的液流とクレマを実装。
- シネマのSSR/SSAO/DoFは外観表示向けです。断面では内部の可読性と正しい描画を優先し、追加効果を制限します。
- 簡易モードの湿潤・液流は外観用のモデルです。GPUモードでは、粉体の位置と湿潤率、落下液体を実際のGPUバッファから描き、回収した量と溶質をレポートへ渡します。
- `src/render/ssfr.js` と `src/gpu/wetting-reference.js` は独立した参照実装。公開画面の物理ソルバーとしては接続していません。

ソースを変更したときはバンドルを再生成し、`js/renderer.bundle.js` を含めてコミットします。公開サイトではビルドやCDN接続は不要です。

```sh
npm ci
npm run build
npm test
npm run test:e2e
```

ブラウザテストは実WebGLのシェーダーとSSFRのコンパイルも検査します。WebGPUの参照実装テストは、テストブラウザにadapterがある場合だけ実行し、ない場合は明示的にスキップします。

CI等でソフトウェアGPUを明示してGPU参照テストまで実行する場合（ハードウェア性能の評価には使いません）:

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium PLAYWRIGHT_SOFTWARE_GPU=1 npm run test:e2e
```

## GPU物理計算（v4.2）

レシピ画面の「物理計算を選ぶ」で自動／GPU物理／簡易モデルを切り替えます。スマホの自動設定は軽量計算で、GPU物理は明示的に選択します。PCの自動設定はGPUを試します。GPUを選んだ場合の粒子数はスマホ32,768／PC100,000（横向きでも同じ）。10万・25万・50万も選べます。液体の粒子枠は別に2,048です。計算世界の秒数と端末の実時間は分けて表示し、遅い端末では時間を飛ばさず計算を待ちます。

GPU上の粉体、輸送、液体回収を結び、TDSとEYはカップに届いた液量・溶質から求めます。診断には水・コーヒー成分・流出液の3つの保存誤差を表示します。途中終了、一時停止、キャンセル、GPU接続喪失にも対応します。

[GPU実装設計と検証範囲](docs/architecture/gpu-solver.md) に数式・単位・近似を記載しています。50万粒子の実行確認は初期のMPMステップのスモークテストです。50万粒子での全抽出や、スマホでのリアルタイム動作を保証するものではありません。WDT・気泡流体・実測校正・格子収束などは残る開発です。

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium PLAYWRIGHT_SOFTWARE_GPU=1 npm run test:gpu
```

## モバイル起動と復帰（v4.2.1）

スマホではWebGPU APIの有無にかかわらず、自動設定は軽量計算と省電力のWebGL表示です。3D読み込みは抽出時計を止めません。3Dをオフにして数値とレポートだけでも使えます。

GPU物理を手動で選んだ場合、準備は12秒、各計算バッチは8秒で応答を監視します。応答がなければGPUを破棄し、同じレシピを軽量モデルで最初から計算することを表示します。待機中も「軽量モードで続ける」で戻れます。キャンセルした初期化が遅れて完了しても、現在の抽出へ接続しません。GPU粒子表示は計算とは別に準備し、表示だけの失敗は計算を止めません。

Pixel相当の画面サイズ／Android UAでの縦横表示、無応答のGPU初期化、途中のGPU失敗、WebGLコンテキスト喪失を回帰テストに追加しました。Pixel 10の実機GPUでの検証は行えていません。

## GPU不要の抽出アニメーション（v4.2.2）

スマホの既定表示は、WebGL／WebGPUを使わないSVGアニメーションです。豆の粉砕、粉の堆積とタンピング、湿潤、抽出液、カップの液面が、画面の抽出時計と同じショットデータに追従します。独立したタイマーを持たないため、一時停止やバックグラウンド時も数値とずれません。これは工程の図解で、3Dの流体計算結果を描いたものではありません。

「表示を変える」を開いて「3Dを表示」を選ぶと、抽出の場面をWebGL表示に切り替えられます。3Dが正常に最初のフレームを描くまでSVGを残し、初期化・シェーダー・コンテキストの失敗時には動くSVGへ戻ります。モーション低減の設定では豆・粉・湯気の装飾的な動きを止め、工程と液面の進み具合を表示します。

## バリスタの作業ごとの場面（v4.3）

| 工程 | 簡易モデルの表示時間 | 登場する道具 |
| --- | --- | --- |
| 計量 | 0–3秒 | 豆、計量皿、スケール、スクープ |
| 粉砕 | 3–7.5秒 | グラインダー、ポルタフィルター |
| WDT | 7.5–10秒 | ポルタフィルター、針、マット |
| タンピング | 10–13秒 | ポルタフィルター、タンパー、マット |
| セット | 13–15秒 | マシン、ポルタフィルター、空のカップ、スケール |
| 抽出 | 15秒以降 | マシン、パック、液流、カップ、スケール |

工程名、次の作業、その工程の設定値を表示します。抽出時間・圧力・流量は抽出の場面から表示し、レポートには準備時間を加えません。SVGの場面切り替え・器具・粉・液面は同じ再生時計を使い、一時停止・再開・やり直しに追従します。動きを減らす設定では装飾的な動きを止め、計量や液量の進行は表示します。GPUモードは実際の計算進捗をこの15秒の準備区間に対応させるため、各場面の実時間は端末に依存します。計量・WDT・装着の描写は作業説明であり、新しい物理計算を追加するものではありません。
